# Второй цикл задачи 2: поддержка истории и надёжность reward

22 октября 2026. Документ создан до резервирования новой когорты и обучения.
Первый внешний test открыт; его результаты используются только для постановки
вопроса. Исходные отчёт, код, веса и статья задачи 2 сохраняются.

## Что проверяем

1. Поможет ли GPT-2 механизм copy из реальной истории, в том числе для треков
   вне его словаря? Это известное семейство pointer/copy моделей, не новая
   архитектура трансформера. Decoder GPT-2 заморожен; обучается малый адаптер
   распределения действий. Улучшение copy само по себе не является эффектом RL.
2. Станет ли reward model полезнее при добавлении исторических откликов и
   причинно рассчитанных агрегатов? Сравниваем с константой и первой neural RM.
3. Даёт ли joint CE+reward дополнительный выигрыш относительно того же copy
   адаптера с CE? Отдельный вариант допускает reward лишь при согласии трёх RM
   о направлении разницы между copy и frozen GPT-2. Это проверка ограниченной
   инженерной идеи, без заявления приоритета или гарантии безопасности.

## Общие действия и информация

Каталог — все item IDs, наблюдавшиеся у train UID до270. GPT-2 сохраняет
16384 head items. Copy распределяет массу по последним64 реальным событиям,
если item входит в train-каталог. Повторные позиции одного item суммируются.
Таким образом достижимая поддержка — head плюс доступные copy items. Все
методы оцениваются на общем train-каталоге; будущие targets не добавляются.
Нулевые вероятности вне поддержки допустимы, пропущенные цели всегда промах.
Popularity и repeat строятся по этому же каталогу; head-only repeat — абляция.
Целевой item/outcome не входит во входы, историю или список действий.

Используются реальные исторические доли прослушивания, известные по записи
с timestamp < запроса. Предполагается доступность outcome по timestamp лога,
как в исходном Task2; задержки доставки/начала-конца прослушивания неизвестны.
Длительности и item aggregates берутся только из train. Статические item
агрегаты RM фиксируются до day200; её обучение — days200–259, calibration —
days260–269. Это исключает текущее событие из собственных item statistics.
Три CatBoost RM, seeds17/42/73. Глубины4/6, до400 деревьев, early stopping
по calibration MSE. Лучший рецепт выбирается по calibration, не test.
Исторические user/state признаки обновляются только реальными прошлыми логами.

## Оптимизация и полный бюджет

Frozen GPT-2 seeds17/42/73 первого Task2 используются раздельно. Адаптер:
сигмоидный gate между GPT-2 и copy; copy softmax над64 позициями с обучаемым
recency и весом прошлого outcome. Gate зависит только от реального префикса.
CE: до1200 updates, batch256, Adam, lr0.01; checkpoints300/600/1200 выбираются
на development NDCG seed17. Остальные seeds наследуют число updates.
Не более40 training contexts/user, равномерно из days240–269, seed271828.
Это ограничение обучающих примеров, не обрезание исходных историй.

От выбранного CE адаптера: дополнительные300 updates, lr0.003, batch256.
Контроли: CE continuation, reward-only, uniform joint CE+reward, gated joint.
Reward coefficients lambda ∈ {0.1,0.5,2,8}, KL beta0.1. Сохраняются все trials.
Reward — ансамблевый прогноз completion. Ожидание по copy считается точно;
по frozen GPT-2 —8 Monte Carlo samples/context с фиксированным RNG. Поскольку
decoder заморожен, градиент математически является градиентом ожидаемой
награды смеси, без необходимости REINFORCE для этого конечного ожидания.
Это contextual-bandit RL адаптера, не новый full-decoder H5 RL алгоритм.
Gate допускает reward только при одинаковом знаке copy-minus-GPT reward
у всех трёх RM. Этот критерий не использует logged target.

Выбор каждого семейства: максимальный development NDCG среди настроек,
у которых predicted reward не ниже CE. Если таких нет — максимальный NDCG,
с явной пометкой нарушения reward guard. Primary — gated joint минус CE
continuation; лучший uniform joint — отдельный контроль. Главная нулевая
гипотеза: ожидаемая user-macro разность NDCG@10 равна нулю. Один primary
bootstrap3000 user clusters, seed161804, среднее метрик трёх model seeds.
CI контрольных сравнений описательные. Не выбирать победителя по test.

Публикуем NDCG/Recall/MAP, coverage/OOV, реальные RM MSE/MAE и кластерные CI,
predicted reward, repeat share, duration, концентрацию, полный поиск/стоимость.
Proxy reward не является измеренной удовлетворённостью или causal value.
H5 остаётся отдельным описательным аудитом исходного исследования; данный
цикл проверяет H1 адаптацию и не выдаёт её за решение динамики пользователя.

Перед test фиксируются code/protocol/model SHA и recipe. Все forecasts
сохраняются до построения labels. Компактные массивы и replay verifier
публикуются отдельно в reports/task2b; сырьё/веса — runs/task2b.
